# Weiqi Tutor

围棋启蒙模型：输入一道简单死活题，理解局面与题目要求，判断正解/错解，并用初学者能听懂的语言解释变化过程。

## 当前阶段

本仓库优先建设可验证的数据与棋理层，而不是先做聊天 UI 或直接微调模型。

1. 解析 SGF 棋盘、先手、注释和变化树。
2. 提取题目分支，并区分正解、错解、变化和未标注分支。
3. 用规则计算验证每一步的棋理事实。
4. 生成结构化监督样本，再训练和评估启蒙模型。

## 已实现

- SGF 解析与嵌套变化分支提取；分支标签存在冲突或缺失时保留为 unknown。
- 围棋棋盘规则核心：连通块、气、提子、自杀禁入、劫点及重复局面检查。
- 逐手回放答案分支，记录落子合法性、提子、己方气数、相邻棋块、打吃和补己方真眼等事实。
- 将来源标签与规则验证结果分开保存；“题库标注正确但规则回放非法”的分支会被隔离，不进入正例训练集。

## 开发与数据构建

要求 Node.js >= 20。

```bash
npm install
npm run typecheck
npm run build
npm run audit:sgf -- ./path/to/sgf-directory
npm run build:dataset -- ./path/to/sgf-directory ./data/processed/supervision.jsonl
```

生成的 JSONL 每行对应一条答案变化线，包含原始标签、规则校验状态、逐手棋理事实和训练资格标记。只有明确标注且没有标签冲突的分支才进入训练候选；变化和未知分支不会被强行赋予正误标签。

## 复用来源

题库与部分围棋基础设施来自项目所有者的 [weiqi-bot](https://github.com/zhangbin2025/weiqi-bot)。

## 设计原则

**规则负责判定，模型负责理解与表达。** 正误标签、提子、气、连接等可验证事实不能交给语言模型猜测。
